## 2. How to run things

- Deploy after any code change: `.venv/bin/modal deploy modal_app.py`. launch.py calls the deployed app by name.
- Launch (records call ids in results/calls.jsonl):
  - `.venv/bin/python scripts/launch.py coin RUN_ID --cell H --seed 0 --cycles 400 --no-std-norm`
  - `.venv/bin/python scripts/launch.py coin_sequence PREFIX --cells H:0,H:2 --cycles 400 --no-std-norm --status-file coin_status_x.json`
    (one orchestrator runs its cells in order; run two orchestrators with distinct status files for two runs at once)
  - `.venv/bin/python scripts/launch.py coin_baseline RUN_ID --n-tasks 64 --n-samples 16` (vLLM on one H100, base model)
- Watch: `scripts/wait.py CALL_ID SECONDS` (blocks until the call ends; run it in the background),
  `scripts/status.py CALL_ID`, `scripts/status.py --tail runs/RUN_ID/trainer.log 40`, `scripts/status.py --file coin_status_x.json`.
- Readout: `PYTHONPATH=. .venv/bin/python scripts/coin_readout.py RUN_ID [RUN_ID ...] [--examples]` copies run files to
  results/coin_runs/RUN_ID/ and prints per-10-step tables. Write-up: scripts/coin_writeup.py; hiding figure:
  `.venv/bin/python scripts/coin_hiding_plot.py h_H_s0 h_H_s1 h_H_s2`.
- Spend: `.venv/bin/modal billing report --start YYYY-MM-DD --resolution h --json`, rows with description "penalty-shape".
  Claude API usage is not logged per call; estimate from call counts.
- Run ids on volume `penalty-shape` (runs/RUN_ID/): grid stage 1 s1_<cell>_s0, stage 2 s2_<cell>_s<seed>, hiding
  h_H_s0..2, smoke_*. Each has run.json, scored.jsonl (every answer with completion and monitor scores),
  measurements.jsonl, trainer.log, checkpoints/.
- Cells (config.COIN_CELLS): A present, B lines, C length, D flag, E count, H state_floor; constants COIN_* in config.py.
  Monitors and prompts in penalty_shape/coin.py (RATING_PROMPT as printed in the paper, RATING_PROMPT_CALIBRATED,
  STATE_PROMPT for cell H); reward in penalty_shape/coin_reward.py. Haiku = MONITOR_MODEL, Sonnet = COIN_SONNET.
- Training defaults (modal_app.train_coin_impl): H200:2, 16 prompts x 16 answers, lr 1e-6, temperature 1.0, answers up
  to 1,024 tokens, held-out eval every 10 steps (64 prompts x 1, all monitors), checkpoint every 25 steps,
  std_norm True unless --no-std-norm, KL 0, entropy 0. Model is always base Qwen3-8B (snapshot_download(MODEL)).
- Cost and time: grid run of 200 steps about $17 (15-28 s per step); hiding run of 400 steps about $43 with monitor
  calls (17-24 s per step). H200:2 is about $11 per hour.
- GPU cap: at most 4 GPUs at once (two H200:2 runs). The workspace is shared: never touch other apps (cmp-grafting,
  mimoagent, praxis-lens) or other volumes; hod-qwen3 (hide-or-delete's D3 data) is read-only for us.

## 3. Pitfalls

- Only the final checkpoint keeps model weights (trainer.max_actor_ckpt_to_keep = 1); earlier global_step_* folders hold
  only data.pt. Weights are FSDP shards (world size 2) plus actor/huggingface/ (config, tokenizer); there are no HF weights.
  To sample from or fine-tune a trained model, merge first, inside the train image with the volume mounted:
  `python -m verl.model_merger merge --backend fsdp --local_dir /vol/runs/RUN/checkpoints/global_step_N/actor --target_dir OUT`.
  No Modal function does this yet. Raise max_actor_ckpt_to_keep if intermediate checkpoints will be needed.
- Final weights worth using: s1_E_s0 at 200 (names no sides, accuracy about 0.9), h_H_s2 at 400 (half letter traces),
  h_H_s0/s1 at 400 (minimal readable traces), B seeds 0/1 at 200. C seeds and E seed 1 end collapsed (chance accuracy).
- coin_baseline and train_coin_impl have no model_path option; both use the base model. Add one for probes and
  fine-tuned starts.
- Scripts need `PYTHONPATH=.` (the package is not installed in .venv).
- Modal kills containers now and then with no error; runs resume from the last checkpoint (async_save is off, so the
  resume marker is written). Function timeout 24 h. A relaunch with the same RUN_ID and a larger --cycles continues that
  run from its last checkpoint (start_run resumes when checkpoints/latest_checkpointed_iteration.txt exists).
- Local watchers die with the laptop; Modal runs keep going. Volume listdir is rate-limited; retry.
- No Gemini key: Haiku stands in for their Gemini-2.5-Flash monitor.
- The cell H counter gave 20-33% of letter traces zero lines. Not yet measured whether the same trace gets different
  counts on a rerun (noise) or the counter is systematic about some forms.
- Standard GRPO divides by the group's spread: when all 16 answers are correct, tiny penalty differences are scaled to
  full size and the model shortens until it breaks (C, E seed 1). Use --no-std-norm when penalties are small.
- Entropy bonus: hide-or-delete saw entropy go 0.08 -> 11 in 24 steps at coefficient 0.02 with mean-only GRPO,
  producing junk (HANDOFF_20260829_evening.md there). Start near 0.001 and log entropy.
- Fine-tuning (verl at 8f8b122, not built here yet): `torchrun --standalone --nnodes=1 --nproc_per_node=N -m
  verl.trainer.sft_trainer`, config verl/trainer/config/sft_trainer_engine.yaml, parquet with a `messages` column,
  per-message chat-template rendering, set the learning rate explicitly (default 1e-3). Qwen3's template drops <think>
  content, which does not matter here because the reasoning sits inside the visible answer, but check that the rendered
  training text matches the RL prompt exactly (system prompt starting with \no_think, enable_thinking False).
